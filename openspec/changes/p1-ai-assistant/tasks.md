## 1. The path through the API

Each slice is its own pull request, stacked in order; each passes `make check` and `make test` on its own.

- [ ] 1.1 The delegated read token (design D2): minted by the API per turn (Ed25519, its key in the secret store,
  person, organisation, turn, the AI tools' scope, at most 5 minutes, single turn) and verified as an `agent`-class
  principal with the person's roles; every write refused to it; audited as the AI on behalf of the person. Tests
  `// req: AI-01`, `// req: ai/proposals The orchestrator holds no write credential`, an attack test that the token
  cannot write, outlive its turn or read another organisation (`// asvs:`).
- [ ] 1.2 The API's internal listener (design D4) for the AI service's identity only, with `model-call` running
  `ai.Router.Run` as the person (the switch, budgets, routes, the record) and its contract
  `contracts/openapi/fyniq-internal.v1.yaml` generated by `make openapi`; not reachable through the public listener.
  Tests `// req: AI-P2`, `// req: ai/proposals The orchestrator holds no write credential`.

## 2. The semantic layer

- [ ] 2.1 `internal/semantic` (design D6): the measures and dimensions, compiled to the balance service and the reports,
  and typed facts with their IDs, ledger revision and lineage link; `POST /v1/metrics:query`. Each measure tested equal
  to the statement line or report it names on the sample company. Tests `// req: AI-03`, `// req: AI-68`.
- [ ] 2.2 Result limits (design D6): row caps, column allow-lists, statement timeouts and a token budget per result,
  summarising what is larger. Tests `// req: AI-04`.

## 3. The tool registry

- [ ] 3.1 `contracts/ai/tools/` (design D5): one YAML per tool, generating the model's tool definitions; versioned and
  contract-tested; `TestTheAIToolsAreReadOnly` checks the real registry. Tests `// req: AI-19`, `// req: AI-P2`.
- [ ] 3.2 The tools through the internal `tool` operation as the person: `metrics.query`, `records.get`,
  `records.search`, `lineage.explain`, `checks.list`, `checks.explain`, `packs.get`, each returning typed facts. Tests
  `// req: AI-P1`, `// req: AI-01`, `// req: AI-68`.
- [ ] 3.3 `calc` in the AI service: exact decimals on facts and constants, its result a fact naming its inputs. Tests
  `// req: AI-P6`.

## 4. Exclusions and untrusted text

- [ ] 4.1 The exclusion policy (design D8) on every AI-principal read: the never-send fields by record type, payroll
  only with the new setting `ai.payroll_access` (off, dual controlled) and the person's payroll right, an Owner's added
  exclusions (dual controlled, never removing the never-send list); the output filter for NRIC and bank-number shapes.
  Tests `// req: AI-02`, `// req: AI-20`.
- [ ] 4.2 Untrusted text quoted as `untrusted_text` in tool results and screened through the `Screening` port with
  prompts and answers, failing closed. Tests `// req: AI-18`, `// req: AI-P7`, `// req: AI-25` (organisation text
  labelled untrusted).
- [ ] 4.3 CTL-AI-06 (design D8): planted NRIC, bank numbers and payroll in the sample company reach no recorded model
  request, in `make test` and weekly, with its report as evidence; `compliance/controls/CTL-AI-06.yaml` running. Test
  `// req: CTL-AI-06`.
